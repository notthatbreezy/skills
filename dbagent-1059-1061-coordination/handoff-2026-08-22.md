## Accepted two-exact-IP pilot

The pilot now supports endpoint-dependent NAT using exactly two endpoint-bound
public IPv4 observations:

1. `https://api.ipify.org`
2. `https://ifconfig.me/ip`

The implementation:

- Canonicalizes and validates each public dotted-quad IPv4.
- Rejects malformed, private, reserved, IPv6, ambiguous, converged, swapped,
  rotating, or third-address evidence.
- Requires three stable samples with exact endpoint attribution.
- Rechecks the exact pair before policy phases and before each firewall
  mutation.
- Creates two separate `/32` rules per PostgreSQL server.
- Uses four campaign rules total for primary plus replica.
- Never uses a range, subnet, wildcard, `0.0.0.0`, or Azure-services rule.
- Performs each rule as a separately serialized Bicep
  Validate → WhatIf → Create unit.
- Verifies the previewed resource identity before mutation.
- Writes private-ledger `pending`, performs Create, reads back exact inventory,
  then writes `applied`.
- Requires exact staged inventory after the first rule and exact A+B inventory
  after the second.
- Requires PostgreSQL `inet_client_addr()` to be a member of the approved pair.
- Persists only the boolean `observedClientInApprovedPair`; it does not expose
  the member, provider, raw address, rule name, or IP-derived hash.
- Fails closed and performs exact campaign-owned teardown on any uncertainty.
- Is deliberately non-idempotent: Create-only WhatIf rejects reruns rather than
  adapting existing rules.
